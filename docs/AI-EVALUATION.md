# AI 对照评测记录

## 口诀与全阶段搜索的功能冒烟测试

在上述 3 秒对照之后，接入口诀战术与最多 12 组采样；在当前 Termux 环境、Node.js v26.4.0 下执行：

```sh
npm run eval:ai -- --seeds 2 --hands 1 --opponent advanced-no-tactics --all-phases true --budget-ms 3000 --progress-every 1
```

每个种子交换座位，对照方使用加入口诀前的高级基础策略，共 4 局。口诀加全阶段搜索方赢 3 局、对照方赢 1 局；双下分别为 0 和 1，升级点数为 4 和 3。前者 153 次出牌决策中完成至少一组模拟 107 次、模拟改变建议 4 次；平均决策耗时约 947 ms，P95 约 2.53 秒，P99 约 3.01 秒。

这只是两个种子的功能与耗时冒烟测试，**不能据此判断胜率或证明策略更强**。每场只打一局，没有代表真实多局升级对抗；同步测量也不等于服务端工作线程的端到端延迟。历史条件和参数可能已变化，下面的早期评测不能当作当前策略的胜率。

三组胜负、双下、升级点数及各策略的决策次数、完成模拟次数和改变决策次数与 1 秒测试完全相同。3 秒测试中，全阶段搜索的单次决策最长约 443 ms；1 秒测试最长约 340 ms。两次耗时受设备负载影响，不能用来认为 3 秒预算本身让计算变慢。当时每个行动最多只采样 4 组未知牌，每次最多比较 4 个候选行动；在这批局面中，搜索未用满 1 秒预算，所以提高到 3 秒没有增加推演。

这仅是两个种子的初步检查，不能证明任何策略达到人类水平或不会超过人类。当时模拟只供参考；之后已按用户要求接入口诀战术和全阶段搜索，详见本文最上方。完整历史数据见 [ai-three-strategy-results-3s.json](ai-three-strategy-results-3s.json)。

## 全阶段搜索：200 局配对对照

2026-11-15 在当前 Termux 环境、Node.js v26.4.0 下运行：

```sh
npm run eval:ai -- --seeds 100 --hands 1 --opponent advanced-no-search --all-phases true --budget-ms 300 --progress-every 5
```

每个种子各打两局并交换队伍座位，共 100 组、200 局。双方均使用同花顺保护和大王跟牌评分，只有全阶段搜索方开启模拟。每次搜索的同步计算预算为 300 ms；这不是服务端后台预算的实战测量（当时为 1 秒，现已调整为 3 秒）。

| 指标 | 全阶段搜索 | 关闭搜索 |
| --- | ---: | ---: |
| 胜局 | 103 | 97 |
| 胜率 | 51.5% | 48.5% |
| 双下 | 42 | 53 |
| 升级点数 | 207 | 220 |

100 组交换座位的结果中，全阶段搜索方两局都赢 19 组、各赢一局 65 组、两局都输 16 组。以种子为单位计算，搜索方胜率的配对正态近似 95% 区间约为 45.7%–57.3%；对 35 组非平局配对做双侧符号检验，p 约为 0.736。这个样本不能证明搜索比关闭搜索更强，也不能证明两者实力相同。每场只打一局，不能推断整场胜率。

搜索方共进行 8,476 次出牌决策，5,932 次完成至少一组模拟，360 次改变基础建议。同步评测平均决策耗时约 69 ms，P95 约 212 ms，P99 约 300 ms；对照方平均约 1.86 ms。预算、设备负载和样本是否及时完成都会影响结果，因此重复运行未必得到完全相同的对局和耗时。

## 全阶段搜索的初步检查

2026-11-15 在当前 Termux 环境、Node.js v26.4.0 下运行：

```sh
npm run eval:ai -- --seeds 10 --hands 1 --opponent advanced-no-search --all-phases true --budget-ms 300
```

每个种子交换一次座位，限每场 1 局，共 20 局。双方均使用新的同花顺保护及大王跟牌评分，区别是高级方开启全阶段模拟，对照方关闭搜索。全阶段方赢 11 局、对照方赢 9 局；双下分别为 4 和 5，升级点数分别为 20 和 22。全阶段方 840 次出牌决策中，612 次完成至少一组模拟，31 次因模拟改变基础建议。高级决策平均约 135 ms，P95 约 301 ms；对照平均约 3 ms。耗时包括同步评测开销，会随设备和负载变化。

这是少量、并非独立的单局样本，不能证明胜率提升；评测使用每次 300 ms，当时服务端后台分析预算为 1 秒，两者的采样完成率和结果可能不同。当时模拟使用少量未知牌分配与初级策略推演，不代表真实玩家必然如此出牌。此前直接依据少量样本中最高平均分改变建议时，同一组 20 局只赢 2 局；之后改为在足够样本支持时才调整建议。

## 早期残局搜索评测

2026-11-15，在当前 Termux 环境、Node.js v26.4.0 下运行。每个种子交换一次高级队伍的座位；每场最多打 4 局，每组共 30 个种子、60 场、240 局。首局发牌配对；后续行动和进还贡可能不同。运行命令：

```sh
npm run eval:ai -- --seeds 30 --hands 4
npm run eval:ai -- --seeds 30 --hands 4 --opponent advanced-no-search
```

| 对照 | 高级胜局 | 对照胜局 | 高级双下 | 对照双下 | 高级升级点数合计 | 对照升级点数合计 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 高级（含搜索）对初级 | 122 | 118 | 58 | 55 | 266 | 247 |
| 高级（含搜索）对高级（关闭搜索） | 121 | 119 | 64 | 58 | 268 | 250 |

升级点数是每局获胜方的升级数之和，不等于队伍实际等级变化：等级封顶、打 A 及重置可能影响实际结果。这些对局在 4 局上限内都未结束整场，不能得出整场胜率。

两组中，高级策略的平均决策时间分别约为 2.48 ms 和 2.65 ms，P95 分别约 10.23 ms 和 10.72 ms，P99 分别约 42.08 ms 和 42.87 ms。初级对照的平均/P95/P99 分别约为 1.06/3.65/9.41 ms；关闭搜索的高级对照约为 1.52/5.29/16.94 ms。统计包含所有职责和局面，耗时依设备与负载而异。

目前胜局数量接近，样本中的多局结果也并非彼此独立，不能证明高级或搜索在真实对局中有稳定优势。建议增加种子和完整场数，并与更强的策略或真人对照；离线模拟使用初级策略推演，且不利用对手的历史行为推断手牌，存在模型偏差。

另外以相同的前 5 个种子、交换座位，每场最多进行 30 局，观察整场结果：

```sh
npm run eval:ai -- --seeds 5 --hands 30
npm run eval:ai -- --seeds 5 --hands 30 --opponent advanced-no-search
```

高级对初级共完成 10 场，高级赢 8 场、初级赢 2 场，局胜为 61 比 53。开启搜索对关闭搜索共完成 9 场，开启方赢 3 场、关闭方赢 6 场；另有 1 场到 30 局时尚未结束，局胜合计为 68 比 78。这些种子与上表部分重合，不应作为独立样本相加；整场样本很少，尤其无法据此证明搜索有益或有害。
