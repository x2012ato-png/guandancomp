# 掼蛋牌桌

四人两队在线掼蛋。Node.js / Socket.IO 服务端维护权威状态，React 客户端只接收自己的手牌与公开信息。支持朋友入座、机器人补位、断线重连、托管、进贡与连续升级。

## 运行

需要支持直接运行 TypeScript 的 Node.js（建议 Node 24 或更新版本）。

```sh
npm install
npm run dev:server
# 在另一个终端
npm run dev:client
```

打开 Vite 显示的地址。房间号固定为 666888，加入时已预填；每个服务器同时只能有一个房间，房间已存在时请选择加入。四人入座后房主开始；房主可用“加AI”或“AI教练”填满空位。两位对家一队：AI 教练对家是真人时，轮到该真人出牌，出牌按钮下方会显示建议和理由。选择逢人配后，可在下拉框中选择牌型和替换方案；进贡/还贡时选择标记出的牌。还贡牌默认不公开，界面仅向收到还贡的玩家显示还贡记录。手牌结算后可准备下一局，或等待自动开始。

房主还可以在空座位选择“外部 AI”，或点击已有机器人旁的“配置外部 AI”，为每个座位单独选择接口类型并填写地址、模型名称和可选 API 密钥。OpenAI 兼容接口的 Base URL 例如 `https://api.openai.com/v1`；LM Studio 会话模式填写服务器地址，例如 `http://127.0.0.1:1234`。牌局中可点击机器人旁的“配置 AI”修改，切换接口地址时不会沿用旧地址的密钥。密钥仅保存在服务端房间内存，不发送给其他玩家；房间关闭或服务端重启后需重新配置。服务器会向所配置的服务发送该机器人的手牌、其可见的进还贡信息、公开牌局历史和合法候选动作，可能产生服务商费用。游戏服务器必须能访问该地址，`127.0.0.1` 指游戏服务器所在机器；不需要认证的本地接口可将密钥留空。HTTP 连接不加密，使用远程服务时请使用 HTTPS。

外部模型只需从规则引擎提供的合法候选中选择一个编号；连接失败、超时、返回格式错误或选择无效时，服务器向房主提示并使用内置初级 AI 完成该次行动。OpenAI 兼容模式使用非流式 Chat Completions，每次发送完整玩家视图，超时为 15 秒。LM Studio 会话模式使用 `/api/v1/chat`（需要支持此接口的 LM Studio 版本），首次发送完整视图，之后发送新增公开历史、变化的玩家视图和当前合法候选，超时为 60 秒。每个机器人每局独立维护会话；新局、配置变更或调用失败后不再续接旧会话，下一次发送完整视图。LM Studio 自身是否保留旧对话记录取决于其设置；游戏只停止引用旧会话。长局中模型的上下文仍会增长，发生接口错误时会按上述方式回退并重建会话。

服务端默认监听 3001，`PORT` 可修改端口；Vite 开发模式默认连接当前主机的 3001 端口，生产构建默认连接当前页面的来源。`VITE_SERVER_URL` 可在客户端构建时指定其他服务端地址。`CORS_ORIGIN` 可设为逗号分隔的允许来源；未设置时允许所有来源。生产部署应配置可信来源、HTTPS，并在反向代理处限制访问。会话和房间仅存在内存，重启后失效；重连凭证保存在浏览器 localStorage。无在线成员的房间在空闲约 10 分钟后清理。房间群聊对房内成员可见，保留最近 100 条消息供重连时查看；消息随房间销毁或服务端重启而清除。

手机竖屏时，可在房间内开始游戏前或对局中点击页面底部的「六行布局」切换显示：四名玩家各占一行，下方两行显示自己的手牌。再次点击可恢复牌桌布局；选择会保存在当前浏览器中。

服务端将当前局的公开出牌、不要等事件按顺序记录到项目根目录的 `played_cards_log.md`，供外部工具读取；新局开始时覆盖旧记录。该文件不在游戏界面显示，也不会提交到 Git。可通过 `GUANDAN_PLAYED_CARDS_LOG` 指定其他文件路径；写入失败会记录到服务端错误日志，不会中断游戏。

外部 AI 教练可在每轮请求 `GET /api/played-cards-log`，例如：

```sh
curl http://localhost:3001/api/played-cards-log
```

成功时返回 JSON：`{"format":"markdown","content":"# 出牌记录：第 1 局\n..."}`，`content` 是日志文件的完整内容，响应禁止缓存。文件尚未生成时返回 HTTP 404 和 `{"error":"LOG_NOT_FOUND"}`；读取失败时返回 HTTP 500 和 `{"error":"LOG_READ_FAILED"}`。服务端重启后，文件仍保留上一局记录，直到新局开始覆盖。接口不需要登录，任何能访问服务端的人都能读取日志；浏览器跨域遵循 `CORS_ORIGIN`，该配置不构成身份验证。

刷新页面或网络中断后，浏览器会使用保存的凭证自动恢复房间和座位。如果凭证丢失，可在玩家离线时输入原昵称和房间号加入，恢复原座位和游戏。房间内昵称必须唯一；昵称和房间号可被其他人知晓，因此此恢复方式适合互相信任的玩家，不能用来验证身份或保护手牌。

```sh
npm test
npm run typecheck
npm run build
```

## 部署到 Render

项目根目录的 `render.yaml` 定义了一个免费 Web Service，由同一个 Node.js 进程提供网页、Socket.IO 和日志 API。`.node-version` 固定 Render 使用的 Node.js 版本。

1. 将项目推送到 GitHub、GitLab 或 Bitbucket 仓库。
2. 在 Render 控制台选择 **New → Blueprint**，连接该仓库，选择包含 `render.yaml` 的分支并创建服务。也可手动创建 Web Service，使用 Node 运行时、构建命令 `npm ci && npm run build`、启动命令 `npm start` 和健康检查路径 `/health`。
3. 等待部署完成，打开 Render 提供的 HTTPS 地址。默认情况下不需要设置 `PORT` 或 `VITE_SERVER_URL`；Render 会提供 `PORT`，客户端会连接到页面所在的地址。

保持单个服务实例：房间和会话保存在进程内，多个实例之间不会共享。服务重启、重新部署或休眠后，房间、对局和会话会丢失；Render 免费实例闲置后会休眠，首次访问需要等待唤醒。Render 默认文件系统是临时的，出牌日志也可能在重启或部署后丢失；需要持久保存时须另配持久存储。`CORS_ORIGIN` 可按需限制浏览器跨域请求，但不能替代访问控制。

## 结构与接口

- `packages/engine`：不可变的纯规则状态机。`createGame`、`reduce`、`legalActions`、`interpret`、`generatePlays`、`beats`、`toPlayerView` 与 `eventsForSeat` 是主要接口；动作携带逢人配替换方案。
- `packages/protocol`：房间、动作、确认消息与玩家视图的 Socket.IO 类型。
- `packages/server`：会话、房间、座位、机器人、限速与逐座位同步。客户端不得指定游戏动作的座位。
- `packages/ai`：只使用玩家视图的 AI 策略，以及供后续搜索策略使用的接口。
- `packages/client`：房间、牌桌、选牌、进还贡和结算界面。

AI 提供“初级”和“高级”两套策略：`createBeginnerPolicy()` 保留初级启发式策略，`createAdvancedPolicy()` 增加同花顺保护、出牌权评估、小手牌拆分和有界采样模拟。“加AI”和真人托管使用初级策略，“AI教练”使用高级策略。教练指导仅按被指导玩家的视图生成并单独发送给该玩家；即使没有能跟的牌，也会等待该玩家阅读建议并手动选择不要。

教练指导先显示口诀战术的基础建议，再在独立工作线程中从开局起比较候选行动；模拟结果通过稳定性检验后可更新建议，教练自己的出牌也使用后台搜索。分析完成后仅更新对应牌局版本。搜索预算为 3 秒，工作线程超过 3.8 秒会结束并回退基础建议。模拟最多比较 6 个候选行动、使用 12 组相同的未知手牌样本；全桌剩余超过 18 张时每次最多推演 12 步，至少 4 组样本中有 80% 支持替代行动且平均优势达到 0.08 分时才调整；残局最多推演 48 步，至少 3 组样本中有 75% 支持且平均优势达到 0.04 分时才调整。采样、候选剪枝和启发式模拟都可能影响结果，不能保证最优。直接调用 `createAdvancedPolicy()` 默认不搜索；需要搜索时可显式传入 `{ search: true }`，并可用 `{ search: true, allPhases: true }` 启用全阶段搜索。

指导区区分已知的进还贡信息和假设持牌，列出采样中各家可能持有的较大点数，以及建议出牌后的参考分组。展开推演可查看不同假设手牌下的后续出牌，并用相同假设对照另一种行动。抽样使用已出牌、剩余张数和可见进还贡记录，部分情况下参考队友上轮不要；样本并非真实手牌或胜率。

各条口诀的具体条件、信息边界及例外见 [docs/COACH-TACTICS.md](docs/COACH-TACTICS.md)。

可以运行 `npm run eval:ai -- --seeds 30 --hands 4` 比较高级和初级，或加上 `--opponent advanced-no-search` 单独比较搜索的影响；加上 `--all-phases true --budget-ms 300` 可评测全阶段搜索及每次计算的截止时间。每个种子交换一次队伍座位；每场最多进行指定局数，提前过 A 则结束。输出包括局胜、双下、升级总数、完整场胜负和决策耗时分布。前几局的发牌配对不代表后续策略分歧后的局面完全相同，结论需要足够多的种子和更强的对手验证。

运行 `node packages/ai/bench/compareStrategies.ts --seeds 2 --hands 4 --budget-ms 3000 --output docs/ai-three-strategy-results-3s.json` 可比较无搜索、仅残局搜索和全阶段搜索。三组两两对照各进行 16 局，每种策略参与 32 局；每个种子交换座位，每场连续进行最多 4 局。2 个种子只适合初步检查，不能支持稳健的胜率结论。

一次对照结果及其限制见 [docs/AI-EVALUATION.md](docs/AI-EVALUATION.md)。

规则默认解释与需要确认的问题见 [docs/RULES-CONFIRM.md](docs/RULES-CONFIRM.md)。

## 验收清单

- 四人创建、加入、选座；房主添加和移除机器人；座满后开局。
- 每人仅收到自己的 27 张手牌，对手仅显示张数；不合法和非自己回合的动作被拒绝。
- 断线重连恢复座位与视图；托管和机器人能完成出牌、进贡和还贡。
- 人类玩家行动没有倒计时；断线后等待重连，除非玩家已开启托管。轮到跟牌时可选择「不要 / 跳过」。
- 选择牌型与逢人配解释，验证顺子、连对、钢板、三带二、各类炸弹及比较。
- 验证抗贡、进贡、还贡、接风、双下、升级和过 A；逐局结算并继续下一局。
- 手机横屏时手牌重叠排成一行，无需横向滚动；多人多浏览器体验一致。

当前洗牌使用以随机种子初始化的确定性 32 位伪随机数，适合开发和友好对局，但不应视作对抗恶意玩家的密码学安全洗牌。部署到不可信玩家环境前应更换为密码学安全的可重放随机源。
